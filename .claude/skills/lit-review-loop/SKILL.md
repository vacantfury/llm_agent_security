# Literature-review loop (this repo)

The owner's collaborative literature workflow for this paper. The library is already LARGE (328 bib entries in the science master `references.bib`, a large `agent_prompt_injection_review.md`, and many downloaded papers across science `literature/llm-security/papers/` + legacy `pdfs/`). So this is almost always **gap-filling for a specific decision**, not a from-scratch review. Never re-search what's already covered.

**Corpus home since 2026-08-02:** the shared literature corpus moved into the science repo (`vacantfury/science`, private; local path recorded in `paper/literature/README.md`) under `literature/llm-security/` — master `references.bib` (328 entries, merged 2026-08-02 from both AI-safety repos' `my_base.bib`, key style unchanged) + per-paper `papers/<paper-name>/` bundles (PDF + `source/`) + legacy flat `pdfs/` + `reviews/` (this repo's is `agent_prompt_injection_review.md`). This repo's own `paper/literature/my_base.bib` now holds only this paper's own (to-be-trimmed) cited subset. All candidate staging and session corrections now happen in the science master bib, not here.

**Storage layout (owner habit, 2026-07-12): each paper lives in its OWN subfolder** — science `literature/llm-security/papers/<paper-name>/` holding the **PDF** *and* a `source/` folder (the extracted arXiv .tex / HTML source) — not a bare flat PDF. Older entries may still be flat PDFs (science `literature/llm-security/pdfs/`); use the subfolder for everything new. Rationale: the source (LaTeX/HTML) is easier and more accurate for me to read than PDF (PDF extraction garbles tables/math/figures — observed 2026-07-12), and it gives the owner a clean local copy too.

## The loop (three phases, session execution)

**Phase 0 — Target the gap (my hands).** Before searching, find what's already covered so the search hits only gaps:
- `python3` parse the science master `references.bib` (`literature/llm-security/references.bib`) for existing titles/keys (entries carry full abstracts — grep titles only, not bodies).
- Skim science `literature/llm-security/reviews/agent_prompt_injection_review.md` section headings (`grep -nE '^#{1,3} '`) — it's organized by attack/defense/eval taxonomy (§3 image attacks, §5 encoding attacks, §6 defenses incl. §6.2 safety classifiers / §6.4 text defenses / §6.5 VLM defenses, §7 eval).
- Check what's already downloaded (`ls` science `literature/llm-security/papers/` — per-paper subfolders now, plus the legacy flat `pdfs/`) — some papers are downloaded but have NO bib entry (e.g. the AutoAttack / adaptive-eval classics). Those just need a bib entry, not a re-download.
- State the concrete gap list before searching.

**Phase 1 — Search + stage candidates (my hands).**
- Search arxiv / Semantic Scholar / OpenAlex / ACL Anthology for the gap topics. Delegate fan-out searches to subagents on a cheaper model (cost discipline) — each returns structured metadata (title, authors, year, venue, arXiv id, url) + a one-line relevance note. Have the subagent VERIFY ids with a real search, not recall.
- **Search tip:** always run at least one query phrased in *solution* vocabulary (what a paper that already fixed this would call itself), not only problem vocabulary — problem-keyed queries miss papers that self-title by their fix.
- **Mechanism-match escalation:** a hit that matches our proposed contribution on *core mechanism* alone (even if application domain or framing differ) always gets promoted to full download+verify — never dismissed at abstract-triage. Mechanism overlap is the most dangerous kind of prior art.
- Append candidate BibTeX entries to the science master `references.bib` (`literature/llm-security/references.bib`), each clearly marked as **unverified** — e.g. a `note = {CANDIDATE — verify+download}` field and a `% CANDIDATE <date>` comment line above it. NEVER present auto-generated metadata as if confirmed (the whole reason for the download+verify step is that auto-bibs carry errors — wrong year, wrong venue, arXiv-vs-published mismatch, hallucinated ids).
- Group candidates by the gap they fill; write a short candidate list (key → title → why it's a baseline/prior-art), then move to Phase 2 (the session downloads).
- **Log the pass:** record this pass's search queries + hit counts to a gitignored `outputs/lit_review/<date>/` file — a thorough search returning nothing is itself evidence of novelty/absence, and it's currently lost at session end.

**Phase 2 — Download + verify (SESSION; house rule 2026-08-21, science `handbook/literature_search.md`).** The session downloads, reads, and verifies; keep the owner informed without asking him to supply or confirm what the session can fetch and verify itself.
- **Per-paper subfolder:** create science `literature/llm-security/papers/<paper-name>/` and put BOTH the PDF and a `source/` folder in it. When I download from arXiv: PDF = `curl -L arxiv.org/pdf/<id>`, source = `curl -L arxiv.org/e-print/<id>` (a gzip'd tar — extract into `source/`).
- **Unclear citation metadata (house rule 2026-08-21).** The session resolves unclear published venues by checking the paper's PDF and official proceedings / OpenReview / publisher record, downloads and reads the version of record, and corrects the staged entry itself. If access or venue remains unresolved after those checks, keep the CANDIDATE entry unverified, record the attempted sources and blocker, and inform the owner; do not ask him to supply a citation, download, or confirmation. Reconcile any duplicate entries against the verified record, then continue to Phase 3.
- **Verify** each candidate's metadata against the real downloaded source, fix the bib entry (drop dropped ones, correct year/venue/authors). This is the accuracy guarantee — auto-bib metadata is wrong often enough that it MUST be checked against the real paper.
- Report to the owner what landed + which candidates the session dropped, corrected, or could not verify. Then Phase 3 for verified candidates; keep unresolved candidates marked CANDIDATE and record the blocker without waiting for owner downloads or citation confirmation.

**Phase 3 — Recheck + write up (my hands).** Only after the session's download+verify:
- Re-read the now-verified bib entries and skim each paper's `source/` (.tex/HTML — **preferred**) or PDF — drop the CANDIDATE markers. For exact numbers/tables, read the source (or WebFetch `arxiv.org/html/<id>`), never trust a PDF-extracted figure.
- **PDF-hard → retrofit to source (owner tip, reinforced 2026-07-19).** If a paper arrived as a bare/flat PDF and it reads badly (garbled tables/math, a claim you can't pin down, or you suspect a newer arXiv version — e.g. a v1 missing a v2 appendix), DON'T push through the PDF: make its science `literature/llm-security/papers/<name>/` folder, put the PDF in it, and `curl -L https://arxiv.org/e-print/<id>` the LaTeX source into `source/`, then read the `.tex`. This is the same per-paper-subfolder layout as Phase 2 — apply it as a *fallback* even for papers that were downloaded flat. (Also re-verify the arXiv version: a downloaded PDF can be a stale v1.)
- Integrate into science `literature/llm-security/reviews/agent_prompt_injection_review.md` under the RIGHT existing section, matching its structure (per-paper subsection with the gap-analysis framing, or extend a "Comparison Baselines" table). Don't append a loose new section if it belongs in an existing taxonomy slot.
- Show the diff before writing; the owner approves.

## Operating principles
- **Gap-fill, don't redo.** The base is big — every search starts from Phase 0's coverage check.
- **Candidates are marked unverified until downloaded + verified (by the session).** No silent promotion.
- **Version of record + evidence tier (house rule 2026-08-05; canonical: science `handbook/literature_search.md`).** The verified bib entry cites the PUBLISHED version where one exists — arXiv ID kept as the preprint pointer (the session resolves unclear venues against the paper and authoritative publication records); a database miss on work younger than ~18 months gets one confirming OpenReview/venue-proceedings lookup before "preprint only" is recorded. Review write-ups label each load-bearing citation's evidence tier — (A) peer-reviewed at a named venue · (B) preprint with substantial uptake · (C) recent unrefereed preprint · (D) unverified by us — and a (C) source may motivate a claim but never by itself carry one.
- **The download+verify step is never OMITTED** — it's the accuracy guarantee, not a formality — and it is **the session's responsibility**: download, read, and verify; inform the owner, never delegate verification to him.
- **Prefer .tex/HTML source over PDF for reading** (PDF extraction adds table/math/figure noise — observed 2026-07-12). Each new paper gets its own science `literature/llm-security/papers/<name>/` subfolder holding the PDF + a `source/` folder.
- **Match `agent_prompt_injection_review.md`'s existing taxonomy** when writing up; it's already organized (attacks §2–5, defenses §6, eval §7, synthesis §8–9).
- Bib key style in the science master `references.bib` is `authorYYYYshorttitle` (e.g. `yong2023lowresource`) — match it.
- Novelty/prior-art checks for a *specific claim* are handled by the sibling `scoop-check` skill, which delegates its downloads back to this loop.
